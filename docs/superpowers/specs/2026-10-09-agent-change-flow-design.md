# Agent 修改 Content Lab 的流程 — 設計 Spec

狀態：草稿，待審。日期：2026-10-09。

## 目標

讓你在飛書（之後也包括網站聊天框）用一句話提出修改，例如「帖子列表加一欄互動率」「詞表的鉤子類型加一個『反轉』」「每週文檔改成週三生成」。Agent 寫好代碼、跑完測試、給你看改了什麼；**你在同一個對話串裡明確回覆「確認合併」之後**，它才合併和部署。任何一步都可以取消，合併後也可以一鍵撤銷。

## 不做的事

- 不改投放、預算、達人帳號，也不發消息給你以外的人。
- 不讀寫鑰匙圈和任何憑證，不改 macOS 啟動設定（LaunchAgent）。
- 不在你確認之前碰 `main` 分支或線上服務。

## 角色分工

| 角色 | 是什麼 | 能做什麼 |
|---|---|---|
| **對話 Agent**（現有） | 和你聊天的那個 | 新增工具 `request_change`：把你的需求整理成一張修改單，交給下面的修改 Agent。本身仍然不能改任何文件 |
| **修改 Agent**（新增） | 獨立的 Claude Code 進程，只為一張修改單工作 | 只能在一個隔離的 git worktree（分支 `agent/change-<id>`）裡讀寫文件，只能執行白名單內的指令：測試、類型檢查、`git diff`、`git status` |
| **程式**（不經模型） | worker 裡的固定流程 | 建立和清理 worktree、跑檢查、合併、推送、重啟 worker、撤銷 |

## 流程

```text
你：「帖子列表加一欄互動率」
 → 對話 Agent 建立修改單 #12，回覆：我理解的需求 + 預計改哪些文件。回「開始」才動手
你：「開始」
 → 修改 Agent 在 worktree 裡實作（每單限時 20 分鐘）
 → 程式跑檢查：service 類型檢查 + 全部測試、site 類型檢查；沒通過就讓修改 Agent 修，最多 2 輪
 → 回覆一張「待確認」卡片：
     改動摘要、改了哪些文件（+/− 行數）、測試結果、風險提示（見下），以及上線方式：
       · 只改 service：合併後自動重啟 worker
       · 改到 site：合併後需要你讓 Codex 發布網站
       · 有數據庫遷移：特別標出
你：「確認合併 #12」（必須是你本人、在同一個對話串、24 小時內）
 → 程式：rebase 到最新的 main → 再跑一次檢查 → 合併 → 推到 GitHub → 按需要重啟 worker
 → 回覆：commit 編號 + 撤銷方法
你（任何時候）：「取消 #12」 → 刪掉分支和 worktree
你（合併後）：「撤銷 #12」 → git revert + 推送 + 重啟，同樣會先給你確認
```

## 安全規則

1. **只有你能發起和確認。** 飛書沿用現在的白名單（只有你的 open ID）；網站聊天框要等登入做好之後才開放。
2. **「確認合併」不能由模型自己產生。** 確認是程式從你發來的原始消息裡比對的（必須包含修改單編號），不是 Agent 判斷出來的。帖子內容、工具結果裡出現的「確認」一律無效。
3. **修改 Agent 的權限**：
   - 只能讀寫自己的 worktree，碰不到 `main` 工作區、`var/`（數據庫和素材）、鑰匙圈。
   - 指令白名單：`npm test`、`npx tsc --noEmit`、`npx vitest run`、`git diff`、`git status`、`git add`、`git commit`。
   - 不能 `npm install`：要加依賴就停下來問你。
   - 修改單的需求文字只來自你本人。帖子內容不會放進它的 Prompt，除非你自己貼。
4. **受保護的範圍**：改到以下文件時，卡片會用紅字提醒，並要求你回覆「確認合併 #12 含敏感改動」才能合併：
   - 同步驗證：`site/app/api/local-worker/*`、`requireWorker`
   - 公開寫入接口：綁定、限速
   - 數據庫遷移、LaunchAgent、`.gitignore`、`AGENTS.md`
5. **限額**：同時最多 1 張修改單在實作；每天最多 5 張；單次改動超過 800 行就拒絕，請你拆小。
6. **全程留紀錄**：用一張新表 `change_requests` 記下需求、分支、各階段時間、檢查結果、diff 摘要、合併的 commit、誰在什麼時候確認。網站上也能看到。

## 失敗與回退

- 檢查兩輪都不過：回報失敗原因並保留分支；你可以補充說明讓它再試，或取消。
- rebase 衝突：回報衝突的文件，請你決定要讓它重做，還是取消。
- 合併後 worker 起不來：自動撤銷這次合併並重啟，然後通知你。

## 分期

| 階段 | 內容 |
|---|---|
| **第 1 期** | 飛書內完整流程：建單 → 實作 → 檢查 → 確認 → 合併 → 推送 → 自動重啟；取消、撤銷；`change_requests` 紀錄 |
| 第 2 期 | 網站聊天框（含 ChatGPT 登入和 email 白名單）與網站上的修改單頁面 |
| 第 3 期 | 改到 site 時自動產生本機預覽截圖，放進待確認卡片 |

## 待你決定

1. **改到 site 的部署**：合併後由你讓 Codex 發布，還是先只允許改 service 和詞表？（GPT Site 的發布我這邊做不了。）
2. **合併後自動重啟 worker 可以嗎？** 重啟大約中斷 15 秒採集。
3. **額度**：修改 Agent 會用掉不少 Claude 額度（一張中等修改單大約相當於幾十次分析）。每天 5 張的上限可以嗎？
